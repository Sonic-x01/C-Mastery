المرحلة الأولى

الأدوات، أول برنامج، ورحلة الكود لحد الـ Binary

C لغة compiled: الكود اللي بتكتبه بيتحوّل مرة واحدة لـ machine code الـ CPU بينفذه مباشرة — مفيش interpreter في النص. ده بالظبط سبب إن الـ Reverser بيشتغل على الـ binary: الكود الأصلي اختفى، واللي فاضل هو تعليمات الـ CPU.

أول برنامج — وتشريحه سطر بسطر hello.c

#include // bring in the declaration of printf int main(void) { // execution of YOUR code starts here printf("Hello, Reverser!\n"); return 0; // exit code 0 = success }
السطرمعناه بالظبط
#include <stdio.h>أمر للـ preprocessor: "انسخ محتوى الملف ده هنا". الملف فيه إعلان (declaration) لـ printf — مش الكود بتاعها. الكود نفسه في مكتبة الـ C (libc / ucrtbase.dll).
int main(void)الدالة اللي بيبدأ منها كودك. int = بترجع رقم صحيح (الـ exit code). void = مش بتاخد parameters.
{ ... }الـ block: جسم الدالة.
printf(...)بتطبع نص منسّق. \n = سطر جديد (byte قيمته 0x0A).
;كل statement لازم يخلص بـ ;.
return 0;بيرجّع 0 لنظام التشغيل = "كله تمام". أي رقم تاني = فيه مشكلة.
🔬
عين الـ Reverser: main مش أول حاجة بتتنفذ

الـ Entry Point الحقيقي للـ binary مش main. الـ compiler بيحط قبلها كود اسمه CRT startup (على Linux: _start ← __libc_start_main، وعلى MSVC: mainCRTStartup) بيجهّز الـ heap والـ arguments، وبعدين ينادي main. أول مهارة في IDA/Ghidra: تعدّي الـ startup وتلاقي main. علامة مميزة: main بتتنادى بـ 3 arguments (argc, argv, envp) وقيمتها الراجعة بتتبعت لـ exit().

الأربع مراحل: من .c لـ .exe pipeline

1. Preprocessgcc -E hello.cبينفّذ #include و#define، وبيشيل التعليقات. الناتج: C "صافي".
→
2. Compilegcc -S hello.cبيحوّل C لـ Assembly (ملف .s). هنا بيحصل الـ optimization.
→
3. Assemblegcc -c hello.cبيحوّل الـ Assembly لـ machine code في object file (.o / .obj).
→
4. Linkgcc hello.o -o helloبيربط الـ object files بالمكتبات وبيطلّع الـ executable (ELF على Linux، PE على Windows).
# See each stage yourself gcc -E hello.c -o hello.i # 1) preprocessed C gcc -S -masm=intel hello.c # 2) assembly in Intel syntax -> hello.s gcc -c hello.c -o hello.o # 3) object file (machine code, not linked) gcc hello.o -o hello # 4) link -> executable # The everyday command (all 4 stages at once) gcc -std=c17 -Wall -Wextra -g -O0 hello.c -o hello ./hello # Linux / WSL hello.exe # Windows # Inspect what you built objdump -d -M intel hello.o # disassemble strings hello # printable strings inside the binary

جرّب دلوقتي: الـ compiler غيّر كودك!

اضغط ⚙ ASM على مثال hello.c فوق. هتلاقي call puts مش call printf! الـ compiler لاحظ إن النص مفيهوش format specifiers وبيخلص بـ \n، فاستبدله بـ puts الأسرع، وشال الـ \n من النص (لأن puts بتضيفه). الدرس: الـ binary مش ترجمة حرفية لكودك — ولما تشوف puts في الـ imports، ممكن الكاتب يكون كتب printf.

printf والـ Format Specifiers output

printf بتاخد "قالب" نصي فيه علامات %، وكل علامة بتتعوض بقيمة من الـ arguments اللي بعده بالترتيب. لازم نوع الـ specifier يطابق نوع القيمة — وإلا ده Undefined Behavior.

#include int main(void) { int age = 25; unsigned int flags = 3735928559u; /* 0xDEADBEEF */ double pi = 3.14159265; char grade = 'A'; const char *tool = "Ghidra"; printf("int : %d\n", age); printf("unsigned : %u\n", flags); printf("hex : %x | %X | %#x\n", flags, flags, flags); printf("padded : [%08x]\n", 0x1337); printf("double : %f | %.2f | %e\n", pi, pi, pi); printf("char : %c (code %d)\n", grade, grade); printf("string : %s\n", tool); printf("width : [%10s] [%-10s]\n", tool, tool); printf("percent : 100%%\n"); return 0; }

⚠️
Format String Bug

متكتبش أبدًا printf(user_input); — لو المستخدم كتب %x %x %x هيقرا قيم من الـ stack، و%n بتكتب في الذاكرة! الصح: printf("%s", user_input);. ده نوع ثغرات حقيقي هنشرحه في المرحلة 15.

التعليقات والـ Exit Code basics

#include /* Multi-line comment: the value returned from main becomes the process exit code. */ int main(void) { // Single-line comment (C99 and later) puts("Something went wrong, returning 3"); return 3; /* shell: echo $? | cmd: echo %ERRORLEVEL% */ }

الـ exit code بيتشاف في الـ shell: echo $? على Linux، وecho %ERRORLEVEL% في CMD. في الـ Assembly هتلاقي القيمة دي في الـ register eax قبل الـ ret من main.

✏️ تمارين المرحلة 01

أنهي مرحلة من مراحل الـ build بتحوّل كود C لـ Assembly؟ Preprocessing (-E) Linking Compilation (-S) Assembling (-c) الـ compilation هي المرحلة اللي بتطلّع ملف .s فيه Assembly، وهي اللي بيحصل فيها الـ optimization. الترتيب: preprocess (نص C) ← compile (Assembly) ← assemble (machine code) ← link (executable). البرنامج عمل compile، لكن ظهر undefined reference to 'calc_key'. المشكلة في أنهي مرحلة؟ الـ Preprocessor الـ Linker الـ Compiler وقت التشغيل (runtime) "undefined reference" رسالة linker: الدالة متعلن عنها لكن مفيش object file أو library فيه الكود بتاعها. الـ compiler اكتفى بالـ declaration. اللي بيدوّر على الكود الفعلي للدالة ويربطه هو الـ linker. فتحت binary في IDA ولقيت call puts بس، ومفيش printf خالص. إيه الاستنتاج الصح؟ الكاتب أكيد استخدم puts الـ binary معمول له obfuscation الـ binary مكتوب بـ C++ ممكن يكون مكتوب printf("text\n") والـ compiler استبدلها بـ puts gcc وclang بيستبدلوا printf بنص ثابت بيخلص بـ \n ومفيهوش % بـ puts — حتى في -O0. الـ binary مش مراية لكودك. فكّر في الـ optimization اللي شفناه بزرار ASM على hello.c. إيه الـ specifier الصح لطباعة قيمة من نوع size_t (ناتج sizeof)؟ %zu %d %lu دايمًا %s %zu هو الـ specifier الرسمي لـ size_t على كل المنصات. %lu بيشتغل على Linux 64-bit بس بيبوظ على Windows 64-bit (لأن long هناك 32-bit). فيه specifier مخصوص لـ size_t بحرف z. أول instruction بتتنفذ لما الـ OS يشغّل الـ executable هي... أول سطر في main الـ Entry Point — غالبًا كود الـ CRT startup اللي بينادي main بعدين أول #include دالة printf الـ Entry Point (مكتوب في الـ PE/ELF header) بيشاور على كود startup زي _start أو mainCRTStartup، وهو اللي بيجهّز البيئة وينادي main. (والـ malware ممكن يغيّر ده أو يشغّل كود قبله زي TLS callbacks.) main هي بداية كودك، مش بداية الـ process. هيطبع إيه: printf("[%5d][%-5d][%05d]\n", 42, 42, 42); [42 ][ 42][42000] [42][42][42] [ 42][42 ][00042] [00042][42 ][ 42] الرقم = أقل عرض، والمحاذاة يمين افتراضيًا. - = محاذاة شمال. 0 = املا بأصفار. الافتراضي محاذاة لليمين بمسافات. - بيعكسها، و0 بيملا بأصفار. اكتب برنامج يطبع السطور دي بالظبط (لاحظ الـ % في آخر سطر):
