المرحلة التاسعة عشر

الـ Processes، الـ Signals، والتواصل بينهم (IPC)

الـ malware نادرًا ما بيفضل process واحد: بيشغّل نسخ من نفسه، وبيشغّل cmd.exe أو /bin/sh، وبيوصّل input/output بتاعهم بـ pipes، وبيعمل shared memory عشان ينقل payload. المرحلة دي بتعلمك إزاي الـ process بيتولد ويموت ويتكلم مع غيره، على Linux الأول (لأن الـ APIs أبسط وتقدر تشغّلها هنا)، وبعدين المقابل في Windows.

fork(): الـ Process بيستنسخ نفسه fork · wait

fork() بتعمل نسخة كاملة من الـ process (الذاكرة، الـ file descriptors، كل حاجة)، والاتنين بيكمّلوا من نفس السطر. الفرق الوحيد: القيمة الراجعة. الـ child بياخد 0، والـ parent بياخد الـ PID بتاع الـ child، و-1 لو فشلت. والـ parent بيستنى الـ child بـ waitpid ويقرا الـ exit status بتاعه.

#define _POSIX_C_SOURCE 200809L #include #include #include #include int main(void) { int value = 10; fflush(stdout); /* see the gotcha below */ pid_t pid = fork(); if (pid < 0) { perror("fork"); return 1; } if (pid == 0) { /* ---- child ---- */ value += 5; /* changes the CHILD's copy only */ printf("[child] value = %d, my parent is %s\n", value, getppid() > 0 ? "alive" : "?"); exit(42); /* exit code for the parent */ } int status; /* ---- parent ---- */ waitpid(pid, &status, 0); /* wait + collect exit status */ if (WIFEXITED(status)) printf("[parent] child exited with %d\n", WEXITSTATUS(status)); printf("[parent] value = %d (unchanged: separate memory)\n", value); return 0; }
⚠️
فخ الـ buffer قبل fork

printf مش بيكتب فورًا، بيحط النص في buffer جوه الذاكرة. وfork بتنسخ الذاكرة كلها، بما فيها الـ buffer. فلو فيه نص لسه متطبعش، هيطلع مرتين. الحل: fflush(stdout) قبل fork. جرّب:

#define _POSIX_C_SOURCE 200809L #include #include #include int main(void) { printf("hello "); /* sits in the stdout buffer */ pid_t pid = fork(); /* the buffer is copied too! */ if (pid == 0) { printf("from child\n"); return 0; /* child flushes "hello from child" */ } waitpid(pid, NULL, 0); printf("from parent\n"); /* parent flushes "hello from parent" */ return 0; }
🧟
Zombies و Orphans

Zombie: child خلص والـ parent لسه معملش wait، فبيفضل في جدول الـ processes (حالة Z في ps) لحد ما الـ parent يقرا الـ status بتاعه. Orphan: الـ parent مات قبل الـ child، فالـ child بيتبناه init/systemd (PID 1). الـ Linux malware بيستغل ده عمدًا في الـ daemonization (تحت).

exec: استبدل البرنامج كله execve

عيلة exec (execl، execv، execvp، …) بتستبدل البرنامج الشغال ببرنامج تاني جوه نفس الـ process (نفس الـ PID، ونفس الـ file descriptors المفتوحة). لو نجحت مش بترجع أبدًا. ولو رجعت، يبقى فشلت. النمط الكلاسيكي لتشغيل أمر: fork ← في الـ child: exec ← في الـ parent: waitpid. (على سيرفر التشغيل هنا مفيش /bin، فالمثال بيعمل exec لنفسه عن طريق /proc/self/exe. على جهازك جرّب execlp("ls", "ls", "-l", (char *)NULL).)

#define _POSIX_C_SOURCE 200809L #include #include #include #include #include int main(int argc, char *argv[]) { if (argc > 1) { /* we are the NEW program image */ printf(" new image running, argv[1] = \"%s\", pid unchanged\n", argv[1]); return 7; } printf("parent: launching a new program\n"); fflush(stdout); pid_t pid = fork(); if (pid == 0) { execl("/proc/self/exe", argv[0], "--stage2", (char *)NULL); /* only reached if exec FAILED */ fprintf(stderr, "exec failed: %s\n", strerror(errno)); _exit(127); /* _exit: don't flush parent's buffers */ } int status; waitpid(pid, &status, 0); printf("parent: child finished with %d\n", WEXITSTATUS(status)); return 0; }
🔬
/proc/self/exe و argv[0] في الـ Linux malware

الـ bots زي Mirai بيعيدوا تشغيل نفسهم بـ arguments مختلفة (stages)، وبيغيروا argv[0] عشان يبانوا في ps باسم بريء زي [kworker/0:1] أو sshd. بيعملوا كمان unlink لملفهم على الـ disk بعد ما يشتغلوا. عشان كده في الـ incident response، ls -l /proc/<pid>/exe بيقولك "(deleted)"، وتقدر تنسخ الـ binary من /proc/<pid>/exe حتى لو اتمسح.

Pipes و dup2: وصّل output process بـ input تاني pipe · dup2

pipe(fd) بتديك اتنين file descriptors: fd[0] للقراية وfd[1] للكتابة، واللي يتكتب في واحد يطلع من التاني. ولأن fork بينسخ الـ descriptors، الـ parent والـ child يقدروا يتكلموا. وdup2(old, new) بتخلي new يشاور على نفس حاجة old: مثلًا dup2(fd[1], 1) = "خلي الـ stdout بتاعي يروح للـ pipe".

#define _POSIX_C_SOURCE 200809L #include #include #include #include int main(void) { int fd[2]; if (pipe(fd) != 0) { perror("pipe"); return 1; } fflush(stdout); pid_t pid = fork(); if (pid == 0) { /* child: the "command" */ close(fd[0]); /* child only writes */ dup2(fd[1], STDOUT_FILENO); /* stdout -> pipe */ close(fd[1]); printf("uid=1000 user=analyst host=lab-vm\n"); /* goes into the pipe */ fflush(stdout); _exit(0); } close(fd[1]); /* parent only reads */ char buf[128]; ssize_t n = read(fd[0], buf, sizeof buf - 1); close(fd[0]); waitpid(pid, NULL, 0); if (n < 0) { perror("read"); return 1; } buf[n] = '\0'; printf("captured %zd bytes: ", n); for (ssize_t i = 0; i < n; i++) putchar(toupper((unsigned char)buf[i])); return 0; }
🔬
النمط اللي لازم تعرفه من أول نظرة: Reverse Shell

لو شفت socket ← connect ← dup2(s, 0) وdup2(s, 1) وdup2(s, 2) ← execve("/bin/sh", …)، ده reverse shell: الـ stdin/stdout/stderr بتوع الـ shell بقوا الـ socket، فالمهاجم بيكتب أوامر من بعيد. في shellcode على Linux x64 هتلاقيها syscalls مباشرة: mov eax, 33 (dup2) وmov eax, 59 (execve) ثم syscall. على Windows نفس الفكرة: CreateProcess("cmd.exe") وSTARTUPINFO.hStdInput/hStdOutput/hStdError = الـ socket، مع flag STARTF_USESTDHANDLES (0x100).

الـ Signals: إشعارات من الـ Kernel sigaction

الـ signal = إشعار بيوصل للـ process فجأة، في أي نقطة: SIGINT (Ctrl+C)، SIGTERM (طلب إنهاء مؤدب)، SIGKILL (إنهاء إجباري، مينفعش تمسكه)، SIGSEGV (وصول ذاكرة غلط)، SIGCHLD (child مات)، SIGTRAP (breakpoint). تقدر تسجّل handler بـ sigaction.

#define _POSIX_C_SOURCE 200809L #include #include #include static volatile sig_atomic_t got_usr1; /* the ONLY safe shared type */ static volatile sig_atomic_t got_term; static void on_signal(int sig) { /* async-signal-safe only: no printf, no malloc in here! */ if (sig == SIGUSR1) got_usr1++; else if (sig == SIGTERM) got_term = 1; } int main(void) { struct sigaction sa = { 0 }; sa.sa_handler = on_signal; sigemptyset(&sa.sa_mask); sigaction(SIGUSR1, &sa, NULL); sigaction(SIGTERM, &sa, NULL); signal(SIGINT, SIG_IGN); /* ignore Ctrl+C entirely */ raise(SIGUSR1); /* send to ourselves */ kill(getpid(), SIGUSR1); /* same thing, by PID */ raise(SIGINT); /* ignored: nothing happens */ raise(SIGTERM); printf("SIGUSR1 received %d times\n", (int)got_usr1); printf("SIGTERM received: %s -> cleaning up and exiting\n", got_term ? "yes" : "no"); return 0; }
⚠️
الـ handler بيقطع الكود في أي نقطة

ممكن الـ signal يوصل وإنت جوه malloc أو printf. لو الـ handler نادى نفس الدالة، الـ state الداخلي هيبوظ. فجوه الـ handler: غيّر volatile sig_atomic_t flag بس، أو استخدم دوال async-signal-safe (زي write و_exit). وده كمان مصدر ثغرات حقيقية (signal handler races، زي CVE-2024-6387 "regreSSHion" في OpenSSH).

#define _POSIX_C_SOURCE 200809L #include #include static volatile sig_atomic_t trap_handled; static void on_trap(int sig) { (void)sig; trap_handled = 1; } int main(void) { struct sigaction sa = { 0 }; sa.sa_handler = on_trap; sigaction(SIGTRAP, &sa, NULL); raise(SIGTRAP); /* a debugger (gdb) intercepts SIGTRAP by default */ if (trap_handled) puts("our handler ran -> no debugger swallowed the trap"); else puts("handler never ran -> a debugger is probably attached"); return 0; }
🔬
Signals كـ anti-debug وكـ control flow

المثال اللي فوق تقنية anti-debug حقيقية في Linux malware: الـ debugger بيبلع SIGTRAP فالـ handler مبيشتغلش. الأخطر: بعض الـ samples بتحط جزء من المنطق جوه handler لـ SIGSEGV أو SIGTRAP وتعمل crash عمدًا، فلو مشيت بالـ disassembly العادي هتفوّت الكود ده. في gdb: handle SIGTRAP nostop pass بيخلي الـ signal يوصل للبرنامج. وعلى Windows المقابل: SEH/VEH (AddVectoredExceptionHandler) + int3 أو قسمة على صفر عمدًا.

mmap: ذاكرة متشاركة وملفات في الذاكرة mmap · mprotect

mmap بتحجز ذاكرة مباشرة من الـ kernel (بالـ pages). MAP_SHARED | MAP_ANONYMOUS = ذاكرة تفضل مشتركة بين الـ parent والـ child حتى بعد fork، عكس الذاكرة العادية اللي بتتنسخ. وتقدر تعمل map لملف كامل وتقراه كأنه array.

#define _DEFAULT_SOURCE /* for MAP_ANONYMOUS */ #include #include #include #include int main(void) { int normal = 1; int *shared = mmap(NULL, 4096, PROT_READ | PROT_WRITE, MAP_SHARED | MAP_ANONYMOUS, -1, 0); if (shared == MAP_FAILED) { perror("mmap"); return 1; } *shared = 1; fflush(stdout); if (fork() == 0) { /* child writes to both */ normal = 99; *shared = 99; _exit(0); } wait(NULL); printf("normal variable : %d (child changed its own copy)\n", normal); printf("shared mapping : %d (child's write is visible)\n", *shared); munmap(shared, 4096); return 0; }
🔬
PROT_EXEC = نفس علامة PAGE_EXECUTE_READWRITE

PROT_READ | PROT_WRITE | PROT_EXEC = 1 | 2 | 4 = 7. لما تلاقي mmap(…, 7, …) أو mprotect(addr, len, 7) (أو 5 بعد كتابة الكود) في ELF، ده غالبًا loader بيفك shellcode أو payload ويشغّله من الذاكرة، نفس فكرة VirtualAlloc + 0x40 على Windows. وmemfd_create + execveat/fexecve = تشغيل ELF كامل من الذاكرة من غير ما يلمس الـ disk (fileless).

Daemonization: إزاي الـ Linux malware بيختفي في الخلفية setsid

#define _POSIX_C_SOURCE 200809L #include #include #include #include #include /* Classic "double fork" daemon recipe (what you will see in Linux bots) */ static void daemonize(void) { if (fork() > 0) exit(0); /* 1) parent exits: shell returns, we become an orphan */ setsid(); /* 2) new session: no controlling terminal */ if (fork() > 0) exit(0); /* 3) can never re-acquire a terminal */ umask(0); /* 4) predictable file permissions */ if (chdir("/") != 0) exit(1); /* 5) don't keep any directory busy */ int devnull = open("/dev/null", O_RDWR); if (devnull >= 0) { /* 6) detach stdin/stdout/stderr */ dup2(devnull, 0); dup2(devnull, 1); dup2(devnull, 2); if (devnull > 2) close(devnull); } } int main(int argc, char *argv[]) { if (argc > 1 && argv[1][0] == 'd') { daemonize(); /* ... the long-running loop would live here ... */ return 0; } puts("usage: ./daemonize d (demo only: forks, detaches and exits)"); return 0; }

لو شفت التسلسل ده (fork ← setsid ← fork ← chdir("/") ← فتح /dev/null) في أول main، اعرف إن البرنامج عايز يشتغل في الخلفية للأبد. الخطوة الجاية: دوّر على الـ persistence (cron، systemd unit، .bashrc) والـ loop الرئيسي.

اقرا CreateProcessW في الـ disassembly

الـ arguments: rcx = اسم التطبيق (غالبًا NULL)، rdx = الـ command line (أهم حاجة، حط breakpoint واقراه)، والـ argument السادس على الـ stack = dwCreationFlags (دوّر على 4 = suspended، و0x08000000 = CREATE_NO_WINDOW)، والتاسع = STARTUPINFO (بص على dwFlags وhStd*)، والعاشر = PROCESS_INFORMATION (منه بيطلع hProcess وhThread اللي هيستخدمهم بعد كده في الـ hollowing).
