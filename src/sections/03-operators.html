العمليات — وخصوصًا الـ Bitwise (لغة الـ Malware)

الـ encryption، الـ hashing، الـ string obfuscation، الـ flags، الـ permissions… كلها bitwise operations. لو مش مرتاح مع ^ و& و<<، مش هتعرف تفك أي decoder. المرحلة دي لازم تبقى طبيعية عندك زي الجمع.

Flags: نفس الطريقة اللي بيستخدمها Windows bitmasks

الـ APIs بتجمع خيارات كتير في رقم واحد، كل خيار bit. لما تشوف في الـ disassembly push 40h قبل VirtualAlloc، لازم تعرف إن 0x40 = PAGE_EXECUTE_READWRITE — علامة خطيرة (ذاكرة قابلة للكتابة والتنفيذ = غالبًا shellcode أو unpacking).

XOR: أهم عملية في الـ Malware Analysis ^

خصائص الـ XOR اللي لازم تحفظها: a ^ 0 = a · a ^ a = 0 · a ^ k ^ k = a (التشفير وفكه نفس العملية) · وتبديلية: a ^ b = b ^ a. عشان كده الـ XOR هو أشهر طريقة لإخفاء الـ strings والـ configs في الـ malware.

#include #include static void xor_buf(unsigned char *buf, size_t len, unsigned char key) { for (size_t i = 0; i < len; i++) buf[i] ^= key; } int main(void) { unsigned char msg[] = "cmd.exe /c whoami"; size_t len = strlen((char *)msg); xor_buf(msg, len, 0x5A); /* "encrypt" */ printf("encoded: "); for (size_t i = 0; i < len; i++) printf("%02X ", msg[i]); printf("\n"); xor_buf(msg, len, 0x5A); /* same op decrypts */ printf("decoded: %s\n", msg); /* Known-plaintext attack: plaintext ^ ciphertext = key */ unsigned char plain = 'c', cipher = 0x39; printf("recovered key: 0x%02X\n", plain ^ cipher); return 0; }
🔬
xor eax, eax مش تشفير!

لما الـ register يتعمله XOR مع نفسه (xor eax, eax) ده مجرد طريقة سريعة وقصيرة لـ eax = 0. أما XOR بين register وقيمة تانية جوه loop بيمشي على buffer — ده decoder ولازم توقف عنده. أداة زي FLOSS وCyberChef بتساعدك تفك الأنواع البسيطة.

Known-plaintext

لو عارف جزء من النص الأصلي (مثلًا كل الـ PE files بتبدأ بـ MZ، والـ URLs بتبدأ بـ http)، تقدر تجيب الـ key بـ XOR بين الـ plaintext والـ ciphertext. ده أساس كسر الـ XOR في الـ samples.

الـ Shifts: منطقي vs حسابي shr · sar

  • << على unsigned = ضرب في 2ⁿ. على signed سالب أو overflow = UB.
  • >> على unsigned = logical shift (بيملا أصفار) ← shr.
  • >> على signed سالب = implementation-defined، وgcc/MSVC بيعملوا arithmetic shift (بيملا بالـ sign bit) ← sar.
  • الـ shift بعدد ≥ عرض النوع (x << 32 لـ 32-bit) = UB.
#include #include int main(void) { int32_t s = -16; uint32_t u = 0xFFFFFFF0u; /* same bits as -16 */ printf("signed -16 >> 2 = %d (0x%08X) arithmetic\n", s >> 2, (uint32_t)(s >> 2)); printf("unsigned u >> 2 = %u (0x%08X) logical\n", u >> 2, u >> 2); printf("1 << 10 = %d\n", 1 << 10); printf("100 >> 3 = %d (100 / 8)\n", 100 >> 3); return 0; }

الـ Rotation: قلب الـ hashing والـ crypto rol · ror

C مفيهاش operator للـ rotate، بس الـ CPU فيه (rol/ror). الـ compilers بتتعرف على الـ pattern ده وبتحوله لـ instruction واحدة. هتشوف ror 13 كتير في API hashing (الـ malware بيدور على الدوال بالـ hash بتاع اسمها بدل الاسم نفسه).

#include #include static uint32_t rol32(uint32_t x, unsigned n) { n &= 31; return (x << n) | (x >> ((32 - n) & 31)); } static uint32_t ror32(uint32_t x, unsigned n) { n &= 31; return (x >> n) | (x << ((32 - n) & 31)); } /* The classic "ROR-13" hash used by a lot of shellcode to find APIs */ static uint32_t ror13_hash(const char *s) { uint32_t h = 0; while (*s) { h = ror32(h, 13); h += (uint8_t)*s++; } return h; } int main(void) { printf("rol32(0x80000001, 1) = 0x%08X\n", rol32(0x80000001u, 1)); printf("ror32(0x80000001, 1) = 0x%08X\n", ror32(0x80000001u, 1)); printf("ror13(\"LoadLibraryA\") = 0x%08X\n", ror13_hash("LoadLibraryA")); printf("ror13(\"GetProcAddress\") = 0x%08X\n", ror13_hash("GetProcAddress")); return 0; }
🔬
ليه ده مهم؟

لو لقيت في sample ثابت زي 0xEC0E4E8E بيتقارن بنتيجة loop فيها ror reg, 0Dh — ده hash لاسم API. المحللين بيحسبوا الـ hashes لكل أسماء الـ APIs ويعملوا جدول عكسي، أو بيستخدموا plugins جاهزة (زي HashDB في IDA). شغّل المثال واحفظ أول hash منهم!
