خريطة الذاكرة والـ Dynamic Memory

كل process ليه مساحة عناوين متقسمة لمناطق: الكود، البيانات الثابتة، الـ globals، الـ heap، الـ stack، والـ DLLs. لما تفتح x64dbg وتشوف عنوان، أول سؤال: العنوان ده في أنهي منطقة؟ الإجابة بتقولك تقريبًا كل حاجة عن البيانات اللي فيه.

شغّله كذا مرة ولاحظ: عناوين الـ heap والـ stack بتتغير كل مرة (ASLR)، لكن الكود والـ globals ثابتين عند 0x40xxxx — لأن Compiler Explorer بيبني executable non-PIE (مش Position Independent)، فالـ image بيتحمل دايمًا على نفس العنوان. مع PIE (الافتراضي في أغلب توزيعات Linux، وزي /DYNAMICBASE على Windows) الـ image نفسه بيتنقل كمان. ولاحظ إن الكود والـ globals قريبين من بعض (نفس الـ image)، والـ stack بعيد جدًا فوق (0x7ff…). من شكل العنوان بس تقدر تخمّن منطقته.

أخطاء الذاكرة: أنواع الثغرات memory bugs

الخطأشكلهالنتيجة
Memory leakحجز من غير freeالذاكرة بتزيد لحد ما تخلص (مشكلة في الخدمات اللي بتشتغل طول الوقت)
Use-After-Free (UAF)استخدام p بعد free(p)الذاكرة ممكن تتحجز لحاجة تانية → قراية/كتابة على object مختلف. من أخطر الثغرات (المتصفحات بالذات)
Double freefree(p) مرتينبيبوظ الـ metadata بتاعة الـ heap → crash أو exploitation
Heap overflowكتابة بعد نهاية الـ blockبيكتب على الـ block اللي بعده أو الـ metadata
Size overflowmalloc(count * size) والضرب عمل overflowbuffer أصغر من المتوقع → heap overflow
Uninitialized readقراية من malloc قبل الكتابةبيانات قديمة (ممكن سرية) بتتسرب
#include #include #include struct session { char user[16]; int is_admin; }; int main(void) { struct session *s = malloc(sizeof *s); strcpy(s->user, "guest"); s->is_admin = 0; free(s); /* s is now dangling */ /* Attacker-controlled allocation of the SAME size often reuses the chunk */ char *msg = malloc(sizeof(struct session)); memset(msg, 0x41, sizeof(struct session)); /* fills user AND is_admin */ if (s->is_admin) /* USE-AFTER-FREE: reads attacker data */ puts("admin access granted?!"); free(msg); return 0; }

المثال ده بيوضح ليه الـ UAF خطير: الـ chunk اللي اتحرر بيتعاد استخدامه، فالـ pointer القديم بيقرا بيانات حد تاني. (مش بنشغله هنا لأن ده UB حرفيًا.) الأداة اللي بتكشف كل الأخطاء دي وقت التشغيل: gcc -fsanitize=address -g على Linux/WSL — اتعود تستخدمها في كل كود بتكتبه.

تكنيك تحليل: Breakpoint على VirtualAlloc

أغلب الـ packers بيعملوا: VirtualAlloc ← يفكوا الـ payload جوه الذاكرة دي ← VirtualProtect لـ executable ← يقفزوا له. فالمحلل بيحط breakpoint على VirtualAlloc، ياخد العنوان الراجع في rax، ويتابع الـ dump بتاعه لحد ما يلاقي MZ أو كود — وده unpacked payload جاهز يتعمله dump.
