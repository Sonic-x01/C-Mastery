C++ للـ Reverser: إزاي تتعرف على C++ في الـ Binary

جزء كبير من الـ malware (RATs، ransomware، loaders حديثة) مكتوب بـ C++. الكود الناتج شكله غريب لو متعود على C: this مستخبي في register، calls على [rax+10h]، أسماء زي _ZN6Beacon10next_sleepEi، ومئات الدوال من الـ STL. المرحلة دي مش عشان تتعلم تكتب C++، دي عشان لما تفتح binary C++ في Ghidra تعرف كل تركيبة بتتحول لإيه، وتعيد بناء الـ classes.

⚙️
الأمثلة هنا C++

زرار التشغيل والـ ASM في المرحلة دي بيستخدموا g++ 15.2 بـ -std=c++20. على جهازك: g++ -std=c++20 -Wall -Wextra file.cpp.

الـ Class = Struct + Functions بـ this مستخبي this

الـ member function مفيهاش أي سحر: هي دالة عادية بتاخد argument أول مخفي اسمه this (عنوان الـ object). على Linux x64 بييجي في rdi، وعلى Windows x64 في rcx (في 32-bit MSVC كان في ecx، واسمها thiscall). والـ methods مش بتاخد أي مساحة جوه الـ object: الـ object = الـ data members بس.

علامة الـ method في الـ disassembly

دالة بتستخدم rcx (Windows) أو rdi (Linux) كـ base pointer للوصول لـ offsets ([rcx+8]، [rcx+10h])، ومحدش بيستخدمه كقيمة عادية = غالبًا method والـ register ده this. في Ghidra: اعمل struct جديد للـ class، وغيّر الـ calling convention للدالة لـ __thiscall، وأول parameter هيبقى this من النوع ده، والـ offsets هتبقى أسماء fields.

الـ mangled names هدية

لو الـ binary مش stripped أو فيه exports، الاسم المشفّر بيديك اسم الـ class والـ namespace وأنواع الـ parameters ببلاش. Ghidra وIDA بيعملوا demangle أوتوماتيك. وextern "C" بيلغي الـ mangling، وده سبب إن exports الـ DLLs المكتوبة بـ C++ غالبًا أسماؤها نضيفة.

Constructors و Destructors و new/delete RAII

new T(args) = خطوتين: operator new(sizeof(T)) (زي malloc) وبعدين نداء الـ constructor على العنوان اللي رجع. وdelete p = الـ destructor وبعدين operator delete. والـ objects اللي على الـ stack الـ destructor بتاعها بيتنادى أوتوماتيك لما الـ scope يخلص (RAII).

اقرا حجم الـ class من operator new

النمط ده بيقولك كتير: الرقم اللي قبل operator new = sizeof الـ class، والدالة اللي بتتنادى بعدها بـ this = الذاكرة الجديدة = الـ constructor. جوه الـ constructor هتلاقي أول سطر غالبًا mov qword ptr [rcx], offset vftable: ده بيحط الـ vtable (تحت)، وعنوانه بيقولك نوع الـ object بالظبط. والـ objects الـ global بتتعمل قبل main (في .init_array على Linux، وفي _initterm على MSVC).

Virtual Functions و الـ vtable vptr

لما class فيها دالة virtual، كل object بياخد pointer مخفي في أول 8 bytes اسمه vptr، بيشاور على vtable: جدول ثابت في .rodata/.rdata فيه عناوين الدوال الـ virtual للـ class دي. النداء c->run() بيبقى: اقرا الـ vptr، اقرا العنوان من الجدول، ونادي. ده الـ dispatch table من المرحلة 08 بالظبط، بس الـ compiler بيعمله لوحده.

إعادة بناء الـ classes من RTTI

الـ RTTI (اللي typeid وdynamic_cast بيستخدموه) بيفضل جوه الـ binary غالبًا، وفيه أسماء الـ classes! على MSVC دوّر في الـ strings على .?AV (class) و.?AU (struct): مثلًا .?AVKeylogger@@ = فيه class اسمها Keylogger. وعلى Itanium الأسماء شكلها 5Sleep و7Command (اللي طبعها المثال). والـ RTTI كمان بيوصف الوراثة (مين بيورث مين). أدوات: سكربت RecoverClassesFromRTTIScript في Ghidra، وplugin ClassInformer في IDA، وOOAnalyzer. ولما تلاقي call qword ptr [rax+18h]: 0x18 / 8 = 3 = الدالة رقم 3 في الـ vtable. افتح الـ vtable وشوف مين.

🧬
الوراثة المتعددة و الـ thunks

لو class بتورث من اتنين (struct C : A, B)، الـ object فيه أكتر من vptr، والـ pointer لـ B جوه C بيبقى على offset تاني. عشان كده هتلاقي دوال صغيرة جدًا اسمها thunks: sub rdi, 10h ← jmp C::method. ده تصحيح لـ this قبل النداء، مش منطق حقيقي. ونفس الشكل في COM interfaces على Windows (QueryInterface/AddRef/Release = أول 3 entries في كل vtable).

الـ catch مش ظاهر في الـ control flow

الكود اللي جوه catch مفيش أي jmp بيوصله: الـ runtime بيلاقيه من unwind tables (.eh_frame/.gcc_except_table على Linux، و.pdata/.xdata + FuncInfo على MSVC). يعني Ghidra ممكن يعرضه كـ "dead code". على Windows: throw = _CxxThrowException، والـ exception code بتاعه 0xE06D7363 (0xE0 + "msc"). لو شفته في x64dbg كـ first-chance exception، ده C++ throw عادي. والـ malware أحيانًا بيرمي exceptions عمدًا عشان يقفز لكود جوه handler ويلخبط التحليل.

الـ SSO في الـ debugger

في MSVC: لو [obj+0x18] (الـ capacity) ≤ 15، النص نفسه في أول 16 byte من الـ object، ولو أكبر، أول 8 bytes pointer للنص. لما تعمل dump لـ std::string مستخدم كـ config value (URL، مفتاح)، اتأكد من الحالة دي الأول. والـ templates: كل نوع بيعمل نسخة منفصلة من الكود (vector<int> وvector<char> = دوال مختلفة)، وكل lambda بتبقى class صغيرة فيها operator() بأسماء زي main::{lambda(int)#1}::operator().
