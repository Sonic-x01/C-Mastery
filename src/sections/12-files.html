الملفات و Parsing البيانات الـ Binary بأمان

نص شغل المحلل هو parsing: PE headers، configs مشفرة، network captures، memory dumps. هنا هتتعلم تقرا وتكتب ملفات binary صح، والأهم: تكتب parser مايقعش لو البيانات بايظة أو معمولة عشان تكسره — لأن أي sample ممكن يكون معمول له كده بالظبط عشان يوقّع أدوات التحليل.

على Windows: استخدم "b" دايمًا مع البيانات الـ binary

الـ text mode على Windows بيحوّل \n لـ \r\n في الكتابة والعكس في القراية، وبيعتبر الـ byte 0x1A (Ctrl+Z) نهاية الملف! لو قريت EXE بـ "r" هتاخد بيانات بايظة. على Linux مفيش فرق، بس اكتب "rb" عشان كودك يبقى portable.

كتابة وقراية binary fwrite · fread

#include #include int main(void) { const char *path = "sample.bin"; const uint8_t data[] = { 0x4D, 0x5A, 0x90, 0x00, 0x03, 0x00, 0x00, 0x00, 0xDE, 0xAD }; FILE *f = fopen(path, "wb"); if (!f) { perror("fopen for write"); return 1; } size_t written = fwrite(data, 1, sizeof data, f); /* (ptr, elem size, count, file) */ fclose(f); printf("wrote %zu bytes\n", written); f = fopen(path, "rb"); if (!f) { perror("fopen for read"); return 1; } fseek(f, 0, SEEK_END); /* jump to the end ... */ long size = ftell(f); /* ... position = file size */ rewind(f); /* back to offset 0 */ printf("file size = %ld\n", size); uint8_t buf[16]; size_t got = fread(buf, 1, sizeof buf, f); /* may return LESS than asked */ printf("read %zu bytes:", got); for (size_t i = 0; i < got; i++) printf(" %02X", buf[i]); printf("\n"); fseek(f, 8, SEEK_SET); /* random access: jump to offset 8 */ int c = fgetc(f); printf("byte @8 = 0x%02X\n", c); fclose(f); remove(path); return 0; }

⚠️
fgetc بترجع int مش char

لازم تخزن نتيجة fgetc في int: الـ byte 0xFF = 255، والـ EOF = -1. لو خزنتها في char (signed)، الـ 0xFF هيبقى -1 والـ loop هتقف في نص الملف!

🐛
Bug كلاسيكي: while (!feof(f))

feof بتبقى true بعد ما محاولة قراية تفشل، مش قبلها. فالـ loop دي بتلف مرة زيادة وبتعالج آخر سطر مرتين أو بيانات قديمة. الصح دايمًا: اختبر نتيجة دالة القراية نفسها.

Parser آمن: الـ Cursor Pattern bounds checking

القاعدة الذهبية: متصدقش أي قيمة جاية من الملف. كل طول وكل offset لازم يتشيك قبل ما تستخدمه. أنضف طريقة: struct فيه pointer للبيانات + الحجم + الموقع الحالي، وكل قراية بتتأكد إن فيه bytes كفاية.

#include #include #include typedef struct { const uint8_t *data; size_t size; size_t pos; int error; /* sticky: once set, every read fails */ } Cursor; static int need(Cursor *c, size_t n) { if (c->error || n > c->size - c->pos) { c->error = 1; return 0; } /* no overflow */ return 1; } static uint8_t rd_u8 (Cursor *c) { if (!need(c, 1)) return 0; return c->data[c->pos++]; } static uint16_t rd_u16(Cursor *c) { if (!need(c, 2)) return 0; uint16_t v = (uint16_t)(c->data[c->pos] | (c->data[c->pos + 1] << 8)); c->pos += 2; return v; } static uint32_t rd_u32(Cursor *c) { if (!need(c, 4)) return 0; const uint8_t *p = c->data + c->pos; c->pos += 4; return (uint32_t)p[0] | ((uint32_t)p[1] << 8) | ((uint32_t)p[2] << 16) | ((uint32_t)p[3] << 24); } static const uint8_t *rd_bytes(Cursor *c, size_t n) { if (!need(c, n)) return NULL; const uint8_t *p = c->data + c->pos; c->pos += n; return p; } /* Format: u32 magic | u16 count | count * (u8 type, u16 len, len bytes) */ static void parse(const uint8_t *buf, size_t size) { Cursor c = { buf, size, 0, 0 }; uint32_t magic = rd_u32(&c); uint16_t count = rd_u16(&c); if (c.error || magic != 0x47464E43) { puts(" bad header"); return; } /* "CNFG" */ for (uint16_t i = 0; i < count; i++) { uint8_t type = rd_u8(&c); uint16_t len = rd_u16(&c); const uint8_t *val = rd_bytes(&c, len); if (c.error) { printf(" record %u: TRUNCATED (claims %u bytes)\n", i, len); return; } printf(" record %u: type=%u len=%u value=%.*s\n", i, type, len, (int)len, (const char *)val); } } int main(void) { const uint8_t good[] = { 'C','N','F','G', 2,0, 1, 4,0, 'h','o','s','t', 2, 3,0, '4','4','3' }; const uint8_t evil[] = { 'C','N','F','G', 1,0, 1, 0xFF,0xFF, 'x' }; /* lies about length */ puts("good file:"); parse(good, sizeof good); puts("evil file:"); parse(evil, sizeof evil); return 0; }
🔬
ليه n > size - pos مش pos + n > size؟

لو n رقم ضخم جاي من الملف، pos + n ممكن يعمل overflow ويلف لرقم صغير فالـ check يعدّي! الصيغة التانية مستحيل تعمل overflow لأن pos <= size دايمًا. التفصيلة دي بالظبط هي الفرق بين parser آمن وثغرة — وهتشوف أدوات تحليل حقيقية وقعت بسببها.

Ransomware = loop على CreateFile/ReadFile/WriteFile

الـ ransomware بيمشي على الملفات بـ FindFirstFileW/FindNextFileW، يفتح كل واحد، يقراه، يشفره، يكتبه، ويغير امتداده بـ MoveFileW. لما تشوف الـ APIs دي في loop واحد مع crypto (BCryptEncrypt أو AES S-Box) — عرفت العيلة. ولاحظ: CreateFile لما تفشل بترجع INVALID_HANDLE_VALUE (= -1) مش NULL — في الـ asm: cmp rax, 0FFFFFFFFFFFFFFFFh.

برنامج على Windows بيقرا EXE بـ fopen(path, "r") والبيانات بتطلع ناقصة وبايظة. السبب؟ fread مبتقراش EXE الملف محمي الـ text mode بيحوّل \r\n وبيقف عند 0x1A — لازم "rb" لازم تستخدم fgets الـ text mode على Windows بيعمل ترجمة لنهايات السطور وبيعتبر Ctrl+Z نهاية ملف. البيانات الـ binary لازم "rb". إيه الفرق بين "r" و"rb" على Windows؟ ليه while (!feof(f)) { fgets(line, n, f); process(line); } غلط؟ feof بيبقى true بس بعد ما قراية تفشل، فآخر لفة بتعالج line القديم تاني feof مش موجودة fgets مبتقراش سطور مفيش غلط الصح: while (fgets(line, n, f)) { ... } — اختبر نتيجة القراية نفسها. إمتى بالظبط بيتعمل set للـ EOF flag؟ parser فيه: if (offset + len > file_size) return ERR; وoffset وlen uint32_t جايين من الملف. المشكلة؟ مفيش مشكلة لازم >= file_size لازم يبقى signed offset + len ممكن يعمل overflow ويلف لرقم صغير، فالـ check يعدّي والقراية تبقى برا الحدود مثال: offset = 0x10، len = 0xFFFFFFF8 ← المجموع 0x8 < size. الصح: if (offset > size || len > size - offset). القيم جاية من المهاجم ومحدودة بـ 32-bit… إيه اللي يحصل لو جمعت رقمين كبار؟ ملف اسمه report.docx أول bytes فيه 4D 5A 90 00. الحقيقة؟ مستند Word عادي ده PE executable متنكر بامتداد مستند ملف ZIP ملف PDF MZ = PE. الـ DOCX الحقيقي ZIP ويبدأ بـ PK\x03\x04. الامتداد كذب. ارجع لجدول الـ magic bytes. في الـ disassembly بعد call CreateFileW لقيت cmp rax, -1 ثم je error. ليه -1 مش 0؟ غلطة في الـ compiler -1 معناها نجاح لأن CreateFileW بترجع INVALID_HANDLE_VALUE (= (HANDLE)-1) لما تفشل، مش NULL دي مقارنة طول الملف من الـ inconsistencies المشهورة في WinAPI: بعض الدوال بترجع NULL للفشل وبعضها INVALID_HANDLE_VALUE. معرفتها بتساعدك تحدد الـ error paths بسرعة. اقرا التعليق في مثال win_read.c. اكتب الـ string "The quick brown fox" في ملف binary، اقفله، افتحه تاني، احسب حجمه بـ fseek/ftell، واقرا كل bytes واحسب مجموعهم (sum) وXOR بتاعهم. اطبع:
